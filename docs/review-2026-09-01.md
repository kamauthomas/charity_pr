# Pre-deployment review — 1 Sep 2026

Review of the Cindy Apparel storefront ahead of the production demo deploy.
Seven issues were found; six are fixed, one is deferred by design.

Original images are **not** recoverable from git (they were never committed). A copy
of every pre-compression image was taken before editing — see *Image compression*
below for what changed and how to judge it.

---

## Fixed

### 1. Shop filter count went stale — `public/js/cindy.js`, `resources/views/pages/shop.blade.php`

**Was:** the toolbar count rendered server-side as `{{ $products->count() }} pieces`
and never changed. Filtering to *Sets* showed 3 cards while the label still read
"16 pieces".

**Now:** the span carries `data-count-label`, and `updateVisibleCount()` recounts
`[data-product-card]:not([hidden])` after each filter click. Also pluralises, so a
single result reads "1 piece" rather than "1 pieces" — `Str::plural` handles the
server-rendered case, the JS ternary handles the filtered case.

### 2. Currency casing disagreed between server and client — `public/js/cindy.js`

**Was:** Blade rendered `KSh 2,200`; the cart drawer rendered `Ksh 2,200`, because
`Intl.NumberFormat('en-KE', {style:'currency', currency:'KES'})` emits "Ksh". Both
spellings appeared on screen simultaneously when the drawer was open over the grid.

**Now:** the formatter produces the number only and the `KSh ` prefix is applied as
a literal, matching the views. A test asserts the page contains `KSh ` and not
`Ksh `, so the two cannot drift apart again.

### 3. Product card price rows did not align — `public/css/cindy.css`

**Was:** `.product-meta` was a plain block, so a one-line title ("Coffee Pleated
Midi") floated its price row higher than two-line neighbours, giving the grid a
ragged baseline.

**Now:** `.product-card` is a flex column, `.product-meta` flexes to fill, and
`.product-card .price-row` takes `margin-top: auto` to pin to the card foot. The
`.price-row` selector is shared with the cart drawer and cart page, so the
`margin-top` rule is scoped to `.product-card` deliberately — do not lift it.

### 4. Regression introduced by fix 3, then fixed — `public/css/cindy.css`

Making `.product-card` a flex container **broke the shop filter**: an author
`display: flex` outranks the user-agent stylesheet's `[hidden] { display: none }`,
so filtered-out cards stayed visible while the count correctly said "3 pieces".

Fixed with an explicit `.product-card[hidden] { display: none; }`. Flagged here at
length because it is invisible to the test suite — the filter is client-side, so
only a browser check catches it. Anything that later adds `display` to a card must
keep this rule.

### 5. Empty favicon — `public/favicon.ico`, `resources/views/layouts/app.blade.php`

**Was:** `favicon.ico` was a 0-byte placeholder; browsers showed a generic page
icon.

**Now:** a real multi-resolution icon (16/32/48/64) generated from the brand logo,
plus a 180px `apple-touch-icon.png`, both linked explicitly from the layout head.

### 6. Page weight — `public/assets/`

**Was:** the logo was a 1254×1254 PNG weighing **1.3 MB**, served on every page for
a ~40px display slot. Product photos were unresized phone-camera originals up to
3024×4032 (~700 KB each). On Kenyan mobile the hero would have crawled.

**Now:**

| | Before | After |
|---|---|---|
| Logo | 1.3 MB | 52 KB |
| `public/assets/` total | 12 MB | 8.7 MB |
| Homepage image payload | 2 948 KB | 1 475 KB |

Logo resized to 256×256 (retina-ample for its slot). Product images capped at
1200 px on the long edge at quality 82, auto-oriented, metadata stripped, and
progressively interlaced.

**Judge this one visually before shipping.** Re-encoding is lossy and irreversible
here, and fashion detail — lace, beadwork, fabric texture — is exactly what
compression damages. The Lilac Contour Set and Black Sculpt Set have the finest
detail; check those first. If any look degraded, the originals are still available
(see below) and can be re-processed at a higher quality.

### 7. No test coverage — `tests/Feature/StorefrontTest.php` (new)

**Was:** only the two stock Laravel example tests.

**Now:** 14 storefront tests, 16 total, 69 assertions, ~0.9s. They cover every
public page, every configured collection and product, 404s for unknown slugs, that
every catalog-referenced image exists on disk, that `hero_product` resolves to a
real product, and the currency casing from fix 2.

The catalog tests are data-driven off `config/cindy.php`, so adding a product with
a typo'd image filename fails the suite instead of shipping a broken image.

## Deferred by design

### Checkout does not submit

`resources/views/pages/checkout.blade.php` posts to `action="#"` with a
`type="button"` submit control. This is intentional pending Safaricom Daraja
credentials, and the page says so.

**Before the demo, decide how to frame this.** The button currently reads "Request
STK Push Soon", which is honest but reads as broken to someone who does not know
the backlog. Either brief the audience or relabel it.

Wiring it up needs: server-side order persistence, a pending-payment record, the
STK Push call, a callback endpoint, and order-status updates. None of that exists
yet — there are no models, migrations, or controllers for orders. The catalog
itself is a static array in `config/cindy.php`, so this is a larger piece of work
than the placeholder implies.

---

## Not fixed — needs your decision

- **Nothing is committed.** Every file described here is untracked against
  `origin/main`. This is the single biggest risk to the demo; one bad `rm` loses
  the storefront. Commit before deploying.
- **`assets/` at the repo root** holds a 14.9 MB `woman.jpg.jpeg` and a
  `copy photo.jpeg`, both unreferenced. Now gitignored and excluded from deploy,
  but still on disk. Delete once you confirm they are scratch.
- **49 of 65 product images are unreferenced** (~4 MB after compression). Harmless,
  but they inflate every rsync.
- **Mobile layout was not verified in-browser.** The window-resize tool did not
  change the rendered viewport, so the 1040px and 700px breakpoints in
  `cindy.css` were read but not seen. Worth one manual check on a phone before
  the demo, since the audience is mobile-first.
